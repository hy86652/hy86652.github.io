康奈尔 INFO 4940 课程（2025 年秋季）的项目：一个用 R 和 Shiny 构建的检索增强生成（RAG）网页应用，我带领 3 人团队完成。

大模型回答得很流畅，却常常没有出处。这个应用只根据刚刚检索到的维基百科页面作答，每个回答都附带编号引用。

## 工作流程

1. **改写问题**：用一个小模型（GPT-4.1 mini）把问题提炼成简短的关键词。早期测试发现，自然语言问题里多余的词会把不相关的页面搜出来，这一步解决了大部分这类问题。
2. **检索**：通过 MediaWiki 搜索 API 拿到候选文章，再获取每个页面的原始 wikitext，截取前约 1200 个字符，避免超出 token 限制。页面缺失时直接跳过，不会让整个回答失败。
3. **回答**：用更大的模型（GPT-4.1）只根据检索到的片段写出一个完整的回答，正文带编号引用，文末附上严格按"标题 — 链接"格式排列的来源列表。

为了让输出格式稳定，提示词改了好几轮。早期版本会漏掉引用标题、编造链接，或者逐页做摘要而不是回答问题。

界面里有可搜索的会话历史，引用可以下载。应用部署在 Posit Cloud 上。

## 局限

每个页面只用了前约 1200 个字符，文章后半部分的信息会被漏掉；原始 wikitext 里的标记也可能干扰模型。下一步可以改用基于向量嵌入的检索，并在交给模型之前先清洗段落。

**技术栈：** R、Shiny、OpenAI API（GPT-4.1、GPT-4.1 mini）、MediaWiki API、Posit Cloud
