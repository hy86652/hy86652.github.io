一个个人的量化研究与执行平台，覆盖完整链路：数据采集、因子研究、策略开发、回测验证、风控管理、实盘执行和绩效监控。单仓库、单进程，同时支持美股（Alpaca，YFinance 作为免费备用源）和加密货币（OKX，CCXT 作为备用源）。我用 Claude Code 来开发它，仓库目前是私有的。

## 怎么搭的

- **数据层**：行情数据存成 Parquet，再用 SQLite 做索引，记录每个品种的频率和数据截止日期，每天收盘后只增量拉取新数据。
- **策略只输出信号**：策略返回目标权重和开仓理由，从不直接下单。仓位计算（Kelly、固定比例或波动率目标）和执行都在下游完成，所以同一套策略代码可以直接在回测和实盘之间切换。
- **自己写的回测引擎**：没有用 backtrader，而是自己写了约 500 行事件驱动的核心代码，撮合逻辑、滑点、费用和涨跌停处理都完全可控。绩效指标包括 Sharpe、Sortino、Calmar 和最大回撤。
- **多层风控**：规则写在 YAML 配置里，每次下单前都会检查，包括单笔止损、单日亏损熔断、回撤熔断、单品种不超过 20% 的仓位上限，以及相关性检查。
- **策略**：动量、均值回归（Z-score 加持仓超时强平）、截面多因子，以及 Kakushadze 论文 *101 Formulaic Alphas* 里的全部 101 个因子，用 pandas 实现并保留了原始编号。
- **适配器模式的执行层**：模拟盘、Alpaca 和 OKX 共用同一个接口，从纸交易切到实盘只需要改一行配置。
- **监控**：Streamlit 做的六页看板，分别是回测、数据、持仓、配置、历史和研究笔记。

## 目前进度

数据、策略、回测、风控和看板都已完成，有单元测试，也有基于 YFinance 真实数据的端到端回测。实盘主循环和券商适配器已经写好，等接入 API Key 就能上线。通知推送还没写。

我给自己定的规则是：任何逻辑都要先用真实市场行为验证过，才能提交。金融数据里充满边界情况，而这恰恰是 AI 生成的代码最容易"自信地出错"的地方。

**技术栈：** Python、pandas、Parquet、SQLite、Streamlit、Alpaca API、OKX / CCXT、pytest
